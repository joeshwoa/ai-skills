# AI Skills — Joshua

A personal library of AI-agent skills, built to work the same way whether
you're using Claude, Cursor, Antigravity, ChatGPT, or another coding/agent
tool — one shared `skills/<name>/SKILL.md` per capability, plus thin
per-tool adapters so each tool discovers it its own way.

**Self-selecting and self-extending:** `skills/skill-router/SKILL.md` is
read first, before any other skill. It auto-picks a matching installed
skill from `skills/manifest.json` with no need to say which one to use,
and — if nothing installed matches the task — searches for a pre-made
skill or converts one of your own MCP repos, or builds a new one from
scratch, and installs it into this repo automatically (commit, push,
sync to Cursor), the same way every skill below was built. See
`skills/skill-router/SKILL.md` and its `references/` for the full
procedure.

**Self-improving:** every skill use ends with a one-line usage report
(logged locally, no git needed — see `skills/skill-enhancer/`).
`skills/skill-enhancer/SKILL.md` reads those reports back, finds
recurring issues or missing coverage, fixes the skill, re-validates, and
ships the update — or does a direct read-through audit when a skill has
no reports yet. Ask to "enhance"/"audit"/"improve" a skill (there's no
background process — it runs when asked, or when an agent notices a
skill just failed and decides a pass is warranted).

## Layout

```
skills/manifest.json # auto-generated index of every installed skill (name + description),
                      # regenerated by skills/skill-router/scripts/build_manifest.py and by install.sh
skills/<skill-name>/
  SKILL.md          # the actual instructions an agent follows
  scripts/          # deterministic code the skill runs (not re-derived each time)
  references/        # docs loaded on demand (schemas, style guides, etc.)
  assets/            # things the skill outputs directly (templates, generated galleries)
  examples/          # worked examples / test fixtures

adapters/
  cursor/            # .mdc rule files for Cursor's Project Rules (project-scoped only —
                      # Cursor has no global rules file; see install.sh's printed text
                      # block for the one-time global paste into Settings > Customize > Rules)
  generic/AGENTS.md   # the emerging cross-tool convention several agents read automatically —
                      # this is also literally what Antigravity reads, at a project's root
                      # AND (installed globally by install.sh) at ~/.gemini/AGENTS.md
  chatgpt/            # text to paste into ChatGPT custom instructions (no file API exists)

tools/install.sh     # drops the adapters into this machine's tool config dirs
```

Note: an earlier version of this repo also had an `adapters/antigravity/` folder
targeting `.antigravity/rules/` — verified against Antigravity's own docs that this
is not a real discovery path (Antigravity reads `AGENTS.md`, project-level and
globally at `~/.gemini/AGENTS.md`) and removed it rather than leave a dead/misleading
adapter around.

- **[omnicinema](skills/omnicinema/SKILL.md)** — cinematic video

  (logos, vector art, textures, UI mockups), voiceover, music, and SFX.
  Runs the real [omnicinema-mcp](https://github.com/joeshwoa/omnicinema-mcp)
  server as a one-shot local command via a small generic MCP stdio
  client (`scripts/mcp_cli.mjs`) — no MCP client registration needed,
  and zero duplicated logic since it talks to the real, unmodified
  server. **Known issue:** omnicinema-mcp's own `.gitignore` currently
  excludes real source files it needs to build (`src/assets/*`) — see
  the skill's SKILL.md for the exact upstream fix.
- **[devuniverse](skills/devuniverse/SKILL.md)** — scaffold a
  production-grade Flutter + Supabase/Firebase/Node project via a
  27-persona virtual engineering agency that debates the stack, builds a
  3D deep-scroll spatial UI module, syncs Figma wireframes, runs a
  compliance/security audit, and drafts Terms/Privacy docs. Runs the
  real [devuniverse-mcp](https://github.com/joeshwoa/devuniverse-mcp)
  server the same one-shot way — verified end-to-end against the real
  server (builds clean from a fresh clone).
- **[flow-studio-director](skills/flow-studio-director/SKILL.md)** — a
  full AI film crew for Google Flow: plans and prices every shot against
  the verified model/credit matrix, writes dense cinematic prompts, keeps
  character dialogue native to the video model (saved Flow voices, no
  dubbing), QCs every take automatically (`qc_clip.py`), assembles with
  loudness normalisation, and can drive Flow in Chrome via Kapture in four
  autonomy modes enforced by `project_state.py` (guided, per-generation,
  per-shot, budgeted autopilot). Platform facts are isolated under
  `references/platforms/` so other video platforms are a new folder.
- **[skill-router](skills/skill-router/SKILL.md)** — the dispatcher: read
  first, always. Auto-selects an installed skill via
  `skills/manifest.json`, and when nothing installed matches, searches
  for or builds a new skill and installs it automatically, following the
  same procedure that built every skill above. See "Adding a new skill"
  below — it's now just a pointer to this skill's own reference docs.
- **[skill-enhancer](skills/skill-enhancer/SKILL.md)** — closes the
  loop: reads the usage reports skill-router logs after every skill use
  (or does a direct read-through audit when none exist yet), finds
  recurring issues and missing coverage, fixes the skill, re-validates,
  and ships the update.

More skills get added here over time, one folder per skill, following the
same layout and the same standard: ask before guessing on anything
subjective (design, scope, tone), never fabricate data, verify the output
before handing it over, and keep every tool's adapter in sync.

## Connecting a skill to your tools

```bash
bash tools/install.sh                    # installs global rules where each tool supports them
bash tools/install.sh ~/path/to/project  # + installs project-level rules and copies skills/ in
```

Run this in a real terminal on your machine — see `tools/install.sh` for
what it does and its ChatGPT/Antigravity caveats (no universal "install a
skill" API exists across tools, so this works by placing files where each
tool already knows to look).

## Adding a new skill

Full procedure (searching for an existing source first, vetting, building
from scratch, and the commit/push/sync checklist):
`skills/skill-router/references/how_to_search_and_install.md` and
`skills/skill-router/references/how_to_build_a_new_skill.md`. Quick
version:

1. `mkdir -p skills/<name>/{scripts,references,assets,examples}`
2. Write `skills/<name>/SKILL.md` — frontmatter (`name`, `description`)
   plus the instructions. See `skills/premium-presentations/SKILL.md` for
   the level of detail to aim for.
3. Add matching entries to `adapters/generic/AGENTS.md` and, if relevant,
   a `.mdc` file under `adapters/cursor/`.
4. Commit and push — `bash tools/install.sh` picks up every skill under
   `skills/` automatically (including regenerating
   `skills/manifest.json`), no need to edit the install script itself.
