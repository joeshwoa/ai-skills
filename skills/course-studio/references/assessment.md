# Assessment design

## Plan
- Weights sum to 100%; each component lists the outcomes it measures.
- Mix: formative (quizzes, exit tickets, worksheets — low stakes, frequent) and summative (project,
  exam). For skills courses ≥ 50% practical.
- School: follow the official split when given (e.g. coursework / practical / final) — ask.

## Writing questions
MCQ: one clear problem in the stem; 3–4 options of similar length; one correct; distractors =
real misconceptions; no "all/none of the above"; avoid negatives (or **bold** NOT); randomise the
correct position across questions (balance A/B/C/D).
True/False: only for clear-cut facts; prefer "correct this statement".
Short answer / code: specify what a full answer contains; give points per element in the key.
Essay / project: always with a rubric.
Every item: outcome id, Bloom level, difficulty (easy/medium/hard ≈ 30/50/20), answer, explanation.

## Rubrics
3–5 criteria × 4 levels (excellent, good, acceptable, needs support), each cell an observable
description (not "good work"). Weights per criterion. Share with students before the task.

## Answer keys and banks
Answer keys are separate files (never printed with the student copy). The question bank workbook
collects every quiz/exercise item with outcome, Bloom, type, answer, points, difficulty — reuse it
to assemble exams (filter by outcome and difficulty).

## Exams
Header: course, duration, total marks, instructions. Sections by question type, easy → hard.
Total time realistic: ~1 min per MCQ, 3–5 per short answer, 10–15 per code task.
