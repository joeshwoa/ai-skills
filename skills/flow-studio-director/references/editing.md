# Editing — the montage, and fixing things without regenerating

## Decide first: is this an edit, or a new picture?

The rule: **if the fix doesn't change what is inside the picture, it's an
edit** (free, instant, lossless to the original). If it changes what is
in the picture, it's generative (costs credits, can introduce new errors).
Always try the edit first.

| Problem | Fix | Tool |
|---|---|---|
| Starts late / ends long / dead air | trim | `edit_clip.py --trim` or edit.json in/out |
| A glitchy half-second mid-clip (warp, extra finger flash) | cut it out and close the gap | `edit_clip.py --cut-out A B` |
| Clip must end still before extending | freeze the last frame | `edit_clip.py --hold-end 1` |
| Slightly slow / needs urgency | speed 1.1–1.3 (pitch preserved) | `--speed` |
| Wrong ratio (16:9 take for a 9:16 post) | reframe with a focus point | `--reframe 9:16 --focus-x 0.4` |
| Framing too wide | punch-in ≤1.2 | `--zoom 1.15` |
| Shaky handheld look not wanted | stabilise | `--stabilize` |
| Colour/brightness off, mismatched between models | grade, warmth, project LUT | `--contrast --saturation --temperature --lut` |
| Noise / soft image | denoise / sharpen | `--denoise --sharpen` |
| Audio hiss, level | denoise, volume | `--audio-denoise --volume` |
| Unwanted music/sound baked in a clip | mute or replace the clip audio | `--mute` / `--replace-audio` |
| Wrong object colour, background swap, remove an object, relight, weather | video-to-video | Omni edit (≤10 s/pass), preservation-list prompt |
| Face drift, wrong wardrobe, anatomy, wrong action, wrong words spoken | regenerate | corrected prompt (qc.md) |
| Clip too short for the beat | Veo 8 s → extend on Lite; else regenerate longer | P9 / new take |

`edit_clip.py` never overwrites the original; re-run `qc_clip.py` on its
output before using it.

## Cutting the film (the montage)

Assemble with `assemble.py edit.json` (full spec in its header). Rules
the editor follows:

- **Trim every generated clip.** Models ease in and drift at the tail:
  cut the first ~0.2–0.4 s and anything after the action settles.
- **Cut on action** — mid-movement, not before or after it; the motion
  carries the eye across the cut.
- **Rhythm.** Social: most shots 1.5–4 s on screen. Emotional beats hold
  longer. Change rhythm deliberately (fast run, then a held shot).
- **Dialogue drives picture.** Never cut a line mid-word; use J/L cuts to
  let lines breathe across cuts and to show reactions.
- **Eyeline and screen direction** stay consistent across cuts (180°).
- **Sound first**: dialogue clean and intelligible → SFX → ambience →
  music under (ducked under narration automatically).
- **Colour match** clips from different models before judging the cut.
- **Titles, supers, CTA, prices** as captions/overlays in post (or baked
  into a keyframe), never generated by the video model.
- **Logo**: `edit.json` `"logo"` — corner, 12–16% width, inside safe zones.

## Captions

From the script, never from speech recognition. The words come from the
plan; the timing comes from measuring the speech in the clips the edit
actually uses (the approved take or its `edit_clip.py` fix), so trims,
cut-outs, speed changes and a model that spoke late are all followed. When
a clip's speech can't be measured (music/ambience covers it) the plan's
windows are used and the shot is reported — check those by eye:
```bash
python3 scripts/captions.py --plan plan.json --timeline final/out.mp4.timeline.json \
    --edit edit.json --out final/captions
```
Burn the `.ass` for social (`"captions": {"file": "final/captions.ass"}` in
edit.json, then assemble again), deliver the `.srt` for YouTube. Arabic ≤40
chars/line, 2 lines max; warnings flag lines that read too fast or that
the edit trimmed away.

## Review cycle

1. `assemble.py edit.json --preview` → rough cut (half-res, fast).
2. Watch it end to end; fix with trims/edits; regenerate only what an edit
   can't fix.
3. Client reviews the rough cut → gate `rough_cut`.
4. Full-quality render, captions burned, final QC → gate `final`.
